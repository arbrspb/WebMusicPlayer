# Подготовка GitHub-релиза

## Почему нужен чистый экспорт

`.gitignore` защищает только будущие добавления. Он не уменьшает старую Git-историю и не удаляет из неё ранее закоммиченные БД, аудио или модели. GitHub блокирует обычные Git-файлы больше 100 MiB и рекомендует держать репозиторий заметно меньше 1 ГБ.

В рабочей папке можно сохранить полную локальную историю, а для публичного GitHub сформировать отдельный минимальный репозиторий.

## 1. Резервная копия локального состояния

```powershell
python tools\backup_local_state.py
```

Скрипт использует SQLite backup API, копирует пользовательские модели/настройки и создаёт SHA-256 manifest. Музыка и сторонние веса не копируются.

## 2. Проверка рабочего дерева

```powershell
python tools\prepare_github_release.py --audit-only
```

Проверяются запрещённые расширения, личные конфиги, приватные пути/IP и крупные файлы в публичном allowlist.

## 3. Чистый экспорт

```powershell
python tools\prepare_github_release.py --output "..\github_release\WebMusicPlayer" --init-git
```

Скрипт откажется перезаписывать непустую папку. В экспорт попадут только source, UI, tests, public docs, example-конфиги и небольшие mapping-файлы. Персональный `folder_keywords.json` исключён; вместо него публикуется обезличенный `folder_keywords.example.json`.

## 4. Публикация

Новый чистый репозиторий можно отправить в новый GitHub repository обычным push. Замена истории существующего `arbrspb/WebMusicPlayer` потребует осознанного force-push и повлияет на старые clones/forks. Этот проект не выполняет force-push автоматически.

Перед любым переписыванием удалённой истории сохраните backup и проверьте экспорт. Если в GitHub уже были настоящие секреты, одной очистки локальной истории недостаточно: следуйте официальной процедуре GitHub по удалению sensitive data.
